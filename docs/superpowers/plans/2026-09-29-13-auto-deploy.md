**Goal:** Every CI-green `main` commit goes live on the Swarm by itself: a small `deployer` service polls `main`, waits until CI has published that commit's images, rolls `api` → `worker` → `caddy` → `backup` onto them in order, and never leaves the site broken, or split between two releases, when a release is bad.

**Architecture:** gitgat.com's self-updating container (poll `git ls-remote`, build, atomically swap, keep old releases, never break the live site) adapted to a registry pipeline: CI already builds and publishes `sha-<7>` images, so the deployer only pulls. Tasks 1 and 2 first make those images multi-arch (`linux/amd64` + `linux/arm64` manifest lists, built on native GitHub runners per architecture and merged under one tag) and drop the stack's blanket x86_64 constraint, because the homelab mixes Raspberry Pis (arm64, including the only schedulable manager) with amd64 VMs. `deploy/deployer/deployer.py` (Python standard library) runs as one Swarm task on a manager with the Docker socket, reads `main`'s SHA with a read-only GitHub token passed to git through its environment, checks `ghcr.io/gitgat/sunday-clays-{backend,frontend}:sha-<7>` with `docker manifest inspect`, then runs `docker service update --image … --with-registry-auth` per service and gates `worker` on `api` reporting the new version on `/api/health`. Swarm's `update_config.failure_action: rollback` plus the existing healthchecks roll a bad service back automatically; the deployer then rolls back the services it already updated in that run (`docker service rollback`, reverse order), so the whole stack is back on the previous release, records nothing as deployed and does not retry that SHA every poll. A service already on the target image is skipped, not updated. While `main` is unchanged, each poll also checks (one `docker service inspect`) that the four services still run the recorded tag, and redeploys it if they drifted. The last deployed SHA, a pause flag, the last failure and a short history live in a JSON file on a named volume; `deployer.py rollback sha-<7>` redeploys an older tag and pauses. Task 3 makes that rollback actually start: an image older than the schema skips `alembic upgrade` instead of crashing on an unknown revision.

## Design (approved 2026-09-29)

- New service `deployer` in the Swarm stack only (`compose.swarm.yaml`; `compose.yaml` bans host binds), 1 replica, manager node, Docker socket mount, read-only secrets: GitHub token (contents:read) and GHCR token (read:packages).
- Every `POLL_INTERVAL` (default 120 s) it reads the main SHA via `git ls-remote` (token injected at call time, never persisted); when it changes and `ghcr.io/gitgat/sunday-clays-{backend,frontend}:sha-<7>` both exist (i.e. CI `ci-ok` passed and publish ran), it updates services in order with `docker service update --image ...:sha-<7> --with-registry-auth`: `api` first (runs alembic upgrade on start; migrations are already expand/contract), wait healthy; then `worker` (stop-first, `stop_grace_period` 5m); then `caddy` and `backup`. `db` never touched. The deployer never updates itself mid-run (it updates its own image last, or is excluded and updated manually — author decides and justifies: see Decision 2).
- Swarm `update_config` `failure_action: rollback` + existing healthchecks give automatic rollback; the last deployed SHA is stored in a small volume; manual rollback = run the deployer's rollback command / service update to an older sha tag.
- Enable repo variable `PUBLISH_ON_PUSH` (publish only from CI-green main) as a documented step.
- `scripts/check_stack.py` + tests gain a rule allowing exactly the deployer's socket bind and manager placement; everything else stays enforced (no `:latest`, `sundayclays_` secret names, x86_64, etc.).
- `deploy/README.md` runbook section: tokens, first deploy, pause/resume auto-deploy, manual rollback, logs.
- Tests: deployer script unit-tested (SHA change detection, skips when images missing, update ordering, stops on failed health and records nothing, idempotent restarts); CI job or existing `scripts/tests` job runs them; coverage expectations consistent with the repo's ratchet.
- Owner constraints: implementers use Sonnet, reviewers Opus; no Claude code-review workflow; Actions budget matters; queue it after Plan 12 and Plan 11.

## Review Focus
1. **A bad release**: a migration that fails, an api that crash-loops or never answers `/api/health` with the new version, a worker that never turns healthy, a caddy that Swarm rolls back after api and worker are already new. Swarm rolls that service back by itself (`failure_action: rollback`); the deployer stops at that service, rolls the services it already updated back to their previous image (so no new api is left serving an old SPA), leaves the later services alone, records nothing as deployed (only `last_failure`), and does not hammer the stack with the same SHA every two minutes. Owner: Task 4 (`test_api_that_never_reports_the_new_version_stops_the_deploy_and_records_nothing`, `test_failed_worker_update_rolls_api_back_and_leaves_caddy_and_backup_alone`, `test_failure_after_api_rolls_the_earlier_services_back`, `test_a_failed_rollback_is_logged_and_the_others_still_roll_back`, `test_a_failed_sha_is_not_retried_every_poll`) and Task 6 (`test_swarm_rolls_back_a_failed_update_of_every_app_service`).
2. **Rolling back across a migration**: the previous release's `api` runs `alembic upgrade head` against a database already at a revision its image does not contain, and its `worker` waits for a schema it will never see as "current". Both must start (expand/contract keeps the old code working), and the database must not change. Owner: Task 3 (`test_an_image_older_than_the_schema_starts_without_migrating`, `test_schema_newer_than_the_image_counts_as_current_after_a_rollback`, `test_schema_is_not_current_while_a_revision_is_pending`, `test_wait_for_schema_keeps_waiting_while_a_revision_is_pending`).
3. **`main` moves before its images exist**: a push whose CI is still running or failed (no `publish`), or a `publish` run that has pushed the backend but not yet the frontend. The deployer waits and deploys nothing until both `sha-<7>` images exist, says so once per SHA rather than every poll, and does not mistake a registry error for "not published yet". Owner: Task 4 (`test_waits_while_either_image_is_unpublished`, `test_waiting_is_logged_once_per_sha`, `test_a_registry_error_is_not_mistaken_for_waiting`), with the existing publish gate tests in `scripts/tests/test_ci_config.py`.
4. **A token leaking**: through `ps`/`docker inspect` argv, git's error output, the deployer's logs or its state file. The GitHub token reaches only the git process's environment; the GHCR token goes to `docker login --password-stdin`; both are redacted from every error. Owner: Task 4 (`test_github_token_reaches_git_only_through_its_environment`, `test_git_failure_is_reported_without_the_token`, `test_failed_login_is_reported_without_the_token`).
5. **A manual rollback racing, or being undone by, the poll loop**: `docker exec … rollback` runs next to the loop in the same container, and the next poll would put `main` straight back. A file lock serialises the two, and a rollback pauses automatic deploys until `resume`. Owner: Task 4 (`test_deploy_lock_keeps_a_rollback_and_the_poll_loop_apart`, `test_rollback_deploys_the_old_tag_in_order_records_it_and_pauses`).
6. **The stack drifting from the recorded release**: a hand `docker stack deploy` with a stale `IMAGE_TAG`, the manual "without the deployer" loop, or a later Swarm rollback leaves services on another release while `main` is unchanged. The deployer notices on the next poll and redeploys the recorded tag; a service that is mid-update is not drift. Owner: Task 4 (`test_drift_from_a_hand_stack_deploy_is_redeployed`, `test_a_service_still_updating_is_not_drift`, `test_unchanged_sha_only_reads_the_running_images`).
7. **No-op updates**: a service already on the target image is never sent `docker service update`, so a restart with an empty state changes nothing, and a manual rollback to the image Swarm already rolled a service back to (status still a stale `rollback_completed`) does not abort before `backup`. Owner: Task 4 (`test_services_already_on_the_target_are_not_updated`, `test_rollback_to_the_image_swarm_already_rolled_back_to_succeeds`).
8. **Another service gaining the Docker socket** (including the `/run/docker.sock` spelling and a bind of a directory that holds it, such as `/var/run` or `/`), a manager placement, or another image taking the deployer's name. Owner: Task 6 (`test_each_rule_rejects_its_violation` cases `socket_on_api`, `run_socket_on_worker`, `var_run_on_api`, `host_root_on_caddy`, `caddy_on_a_manager`, `deployer_runs_another_image`).

9. **An arm64-only breakage** (a dependency without an aarch64 wheel, a base image or apt package missing for arm64, an image that builds but cannot start) must fail the PR, not the publish run; and a publish run where one architecture fails must tag nothing, so the deployer never sees a release that exists for one architecture only. Owner: Task 1 (`test_each_image_job_builds_natively_for_its_one_architecture`, `test_publish_pushes_each_architecture_by_digest_without_attestations`, `test_publish_tags_a_release_only_once_both_architectures_are_pushed`, the `docker-arm64` smoke step) and Task 5 (the deployer in both).

## Decisions
Choices made here where the design leaves room. Reviewers: the names below are what later tasks consume.
1. **Language: a Python standard-library script tested with pytest**, not POSIX sh with bats. `scripts/tests` already runs in the `ratchet` job (`uv run --no-project --with pytest --with pyyaml pytest scripts/tests`), so the tests need no new CI job, runner setup or Actions minutes; bats is not installed anywhere in this repo's CI; the logic (JSON from `docker service inspect`, a health poll with a deadline, atomic state writes, a file lock) is awkward and fragile in sh; and the script passes `mypy --strict`. Every external effect goes through an injected `Deps` (`run`, `fetch`, `sleep`, `clock`, `now`, `log`), so the tests drive a fake git/docker/api and never need Docker or network.
2. **The deployer never updates itself.** Its own service is excluded from `ORDER`, and a `docker stack deploy` with the live tag refreshes it. Reasons: (a) a process cannot supervise its own replacement, since the update kills it before it could check health or record anything; (b) a broken deployer build would take down the one thing that recovers from bad builds, and then a human must step in anyway; (c) its code changes rarely, far less often than the app. The cost is that its image tag can lag the app's. That is harmless, because the deployer never reads its own tag.
3. **Its own image, `ghcr.io/gitgat/sunday-clays-deployer:sha-<7>`**, built from `deploy/deployer/Dockerfile` (`python:3.13.15-slim-trixie` + Debian `git` + the static Docker CLI copied from `docker:28.5.2-cli`, pinned to a patch release like `caddy:2.11.4` and `python:3.13.15`; Dependabot does not track Dockerfiles, so bump it by hand together with the backend and frontend base images). It is not part of the backend image, because git and the Docker CLI do not belong in the app images. CI's `docker` and `docker-arm64` jobs build and smoke-test it (with `load: true`) so a broken Dockerfile fails a PR on either architecture, and `publish.yml`'s `manifest` job tags it **first**, so the backend/frontend pair, the deployer's trigger, is always the last thing a publish run tags. The builds use gha cache scopes `deployer` (`mode=max`) and `deployer-arm64` (`mode=min`, like every arm64 scope; Decision 21), main-only writes like the other images. It is multi-arch like the app images, because it runs on a manager and every schedulable manager is an arm64 Pi (Decision 23).
4. **Token handling.** gitgat splices the token into the clone URL; this plan does not, because a URL shows up in `ps` output and in git's error messages. `git ls-remote` gets `GIT_CONFIG_COUNT=1`, `GIT_CONFIG_KEY_0=http.extraHeader` and `GIT_CONFIG_VALUE_0=Authorization: Basic base64(x-access-token:<token>)` in its environment only, plus `GIT_TERMINAL_PROMPT=0`. Nothing is written to disk. The GHCR token is piped to `docker login ghcr.io --password-stdin` before each rollout, with `DOCKER_CONFIG=/tmp/docker-config` inside the container layer, not in the state volume. Both secrets are read from `/run/secrets/deployer_{github,ghcr}_token`, and every error message has them replaced with `***`.
5. **Health gate.** Swarm already waits for a task with a healthcheck to turn healthy before it counts the task as updated. On top of that, `monitor: 60s` + `failure_action: rollback` on `api`, `worker`, `caddy` and `backup` roll a task back if it fails within a minute. The deployer additionally polls `http://api:8000/api/health` over the stack network until it reports `{"status": "ok", "version": "sha-<7>"}` (`HEALTH_TIMEOUT`, default 600 s) before it touches `worker`. Before each `docker service update` it reads `docker service inspect`: a service whose spec image (without `@digest`) already is the target and whose update state is settled is skipped (`… already on sha-<7>`), so restarts are idempotent without relying on Swarm treating an identical spec as a no-op, and a stale `rollback_completed` status cannot make the CLI fail an update that changes nothing. After each update it re-reads `docker service inspect` and fails when the spec image is not the target, even if the CLI exited 0, which is how a Swarm rollback shows up, or when the update state is `updating`, `paused`, `rollback_started` or `rollback_paused`.
6. **Failure memory is in-process.** A failed SHA goes into a set held by the loop. It is not retried until `main` moves or the deployer restarts, and `sha`/`tag`/`history` are not written ("records nothing"). The state file only gains `last_failure: {sha, tag, at, reason}`, a separate key that `status` shows and nothing else reads. `docker service update --force sundayclays_deployer` is therefore the documented "try that SHA again".
7. **State.** `/state/state.json` (named volume `deployer-state`) holds `{"sha", "tag", "deployed_at", "paused"?, "last_failure"?, "history": [≤ 20 × {"sha", "tag", "at", "how": "auto" | "drift" | "rollback"}]}`, written atomically with `os.replace`. A missing or corrupt file reads as `{}`, which makes the next poll "deploy" `main`; every service already on it is skipped (Decision 5), so that only records it. A rollback records `sha: ""`, so `resume` always goes back to following `main`.
   *Amendment 2026-10-01 (task/19-1-deployer-state):* state moved from the named volume `deployer-state` to a bind of `/var/data/sunday-clays/deployer` at `/state` (NFS-shared by every node), so state survives the task moving managers and `pause`/`resume`/`tag`/`status` run from any manager as a one-off container. `scripts/check_stack.py` now enforces the bind and forbids named volumes everywhere. The text above is kept as written.
8. **One deploy at a time.** `fcntl.flock` on `/state/deploy.lock` wraps every poll, `rollback`, `pause` and `resume`. `pause` issued during a rollout therefore waits for that rollout to finish.
9. **Rollback-safe startup (Task 3).** Without it, the design's "manual rollback" cannot work once a migration has shipped. The older image's `alembic upgrade head` dies with `Can't locate revision identified by '<newer>'`, and its worker's `schema_is_current` never turns true, so it exits 1 after 180 s. `db.database_is_ahead(connection, script)` is true when no revision the database is at is known to the image. `migrations/env.py` then logs a warning naming the database's and the image's revisions and returns without migrating, and `schema_is_current` treats that as current. "Unknown" also covers a divergent history (an image whose chain forked from `main`'s), which now starts without migrating instead of failing loudly. That is accepted: history is linear and only `main` is published, and the warning's revision ids make such a case visible. Only images built after Task 3 have this check, so a manual rollback is supported to releases from Task 3's merge onwards; every tag in the deployer's `history` qualifies, since the deployer ships after Task 3. The `api` command in `compose.yaml` does not change. Rolling back is supported to the previous release, which is what expand/contract guarantees; going further back is only safe if no migration in between removed or renamed anything the older code uses, and the runbook says so.
10. **`DEPLOYER_SECRETS_REV`.** The two tokens expire on their own schedule (fine-grained PATs at most a year), so they are versioned separately from `SECRETS_REV`. Rotating them never touches the app's six secrets.
11. **`GHCR_USER`** (the login that owns the `read:packages` token) is a required stack variable (`${GHCR_USER:?GHCR_USER is required}`; per Plan 01 Decision 22 the message has no `-`). CI's `stack-config` step renders with `GHCR_USER=ci`.
12. **Runs as root in the container.** The host socket is `root:docker 0660`, and Swarm services cannot join host groups. Whoever holds the socket is root on that manager anyway, which is why `scripts/check_stack.py` confines the socket to this one service.
13. **Coverage.** The ratchet measures backend and frontend only, so Task 4 adds the gate for `deployer.py` to the `ratchet` job's existing `scripts/tests` step (`--with pytest-cov … --cov=deploy/deployer --cov-branch --cov-fail-under=90`): no new job, one extra small package. The revision of this plan measured 98% lines+branches on exactly the code below (51 tests). `ruff` and `mypy --strict` on the script stay a local gate (Task 4 Step 5). Task 3's backend lines are covered by the backend suite, whose 99% baseline must not drop.
14. **Poll floor.** `POLL_INTERVAL` below 30 s is refused, so a typo cannot hammer GitHub. The default is 120 s, matching gitgat.
15. **Heartbeat.** The image's `HEALTHCHECK` fails when `/tmp/deployer-heartbeat` is older than 4 h. The heartbeat is touched before every poll, and the slowest full rollout is 4 × 20 min of `UPDATE_TIMEOUT` plus 10 min of health wait plus 3 × 20 min of rolling back after a failure at `backup`, 2 h 30 min, which is under 4 h.
16. **Multi-manager caveat.** Today the task lands on `birdo` (RPi4 8 GB, arm64), or on `bowser` if that pico is up as a manager; `wario` is drained. `deployer-state` is node-local. If the task moves to another manager it starts empty: it records `main` (no `service update` when that is already live) and forgets a pause. The runbook says to pause again after a failover. Pinning it by hostname was rejected, because it would stop the deployer whenever that one manager is down.
   *Amendment 2026-10-01 (task/19-1-deployer-state):* this caveat no longer applies. State is on `/var/data/sunday-clays/deployer`, shared by every node, so a moved task keeps its recorded SHA and any pause. The text above is kept as written.
17. **A failed rollout is rolled back as a whole** (critique I2, option (a)). Swarm only rolls back the one service that failed; left alone, a failure at `caddy` would keep the new `api` and `worker` beside the old SPA until `main` moves. So `deploy()` runs `docker service rollback --detach=false` on the services this run updated, in reverse order (`worker`, then `api`), and the error names them. That is safe for `api` because of Task 3, and it is exactly what Swarm does to the failed service anyway. A rollback that itself fails is logged and the others still run. Services skipped as already on the target (Decision 5) are not rolled back, because this run did not change them.
18. **Drift.** The state file says what was deployed; the services say what runs. When `main` equals the recorded SHA, each poll reads all four services in one `docker service inspect` and, if a settled service runs anything but the recorded tag (a hand `docker stack deploy` with an old `IMAGE_TAG`, the manual loop, a later Swarm rollback), logs `drift: …` and redeploys the recorded tag through the normal path (`how: "drift"`). A paused deployer does not check. If that redeploy fails, the SHA joins the failed set like any other, so it is not retried every poll.
19. **Every merge restarts `worker`, `caddy` and `backup`.** `worker` gets its 5-minute grace, `backup` runs a start-up dump, and `caddy` updates stop-first, which is a few seconds of 502 per merge. Kept as is: stop-first matches the other services and the rollback test in Task 6, caddy holds no state worth protecting, and the runbook says to `pause` around club shoots. Switching caddy to `start-first` is a later, separate change if the blip is noticed.
20. **Quiet waiting.** "`sha-<7>`: waiting for …" is logged once per SHA (a set held by the loop beside the failed set), so a commit that failed CI and never publishes does not log every two minutes. `docker manifest inspect` counts an image as missing only when its error says so (`no such manifest`, `manifest unknown`, `not found`); any other error (auth, network) is `poll failed: …`.
21. **Multi-arch on native runners, not QEMU** (Task 1). Each architecture builds on its own GitHub-hosted runner (`ubuntu-24.04` for amd64; `ubuntu-24.04-arm` for arm64, a standard runner for private repositories since 2026-01-29 with 2 vCPUs, drawing on the plan's included minutes like amd64) and pushes by digest; a small `manifest` job then runs `docker buildx imagetools create` to put both digests under `sha-<7>` and `latest`. Cost, with this repo's numbers: the amd64 `docker` job takes 1.3–2.3 min per run (Sep 29 runs), and the last 30 days saw ≥ 107 PR runs and ≥ 93 `main` runs (the listing capped at 200). The new `docker-arm64` job does the same builds without the tar export and upload, so about 2–4 min at $0.005/min (arm64 is cheaper than amd64's $0.006; the upper end is a frontend PR, which reruns `pnpm install` because the arm64 cache keeps only final layers, below): ≈ 400–800 min ≈ $2–4/month at ~200 runs. `publish` grows from one job (~3 min) to three (~3 + ~3–4 + ~1 min, each rounded up), ≈ 4–5 extra minutes per merge, ≈ 400–475 min ≈ $2–2.50/month at ~95 merges once `PUBLISH_ON_PUSH` is on. So ≈ $6/month worst case after the included 3,000 minutes, about 8% of the $75 budget. QEMU on one amd64 runner would instead bill every arm64 minute at the higher amd64 rate *and* run it 5–10× slower: every frontend PR would run `pnpm install` + `vite build` under emulation (the frontend source changes on most PRs, so its cache rarely helps), and each lockfile or base-image bump would run `apt-get` and `uv sync` emulated. It would also make `docker-arm64` the slowest PR job. The per-architecture gha cache scopes (`<image>` and `<image>-arm64`) keep the two architectures from overwriting each other's cache index, and CI and publish read the same scopes (`test_only_main_writes_the_image_build_cache_that_prs_and_publish_read`). **Cache size.** Every scope shares the repository's 10 GB Actions cache, which GitHub trims least-recently-used first, so a scope is a best effort, not a promise of warm builds. On 2026-09-29 the cache already held 10.74 GB in 800 entries, 7.48 GB of it `buildkit-blob` entries on `main` (526 blobs, many duplicate ~109 MB layers left by `mode=max` over successive `main` runs). Four more `mode=max` scopes would roughly double the BuildKit footprint and evict `main`'s amd64 cache, turning the times above into cold builds. So: (1) the controller deletes stale blobs before Task 1 (controller step "Before Task 1"); (2) the amd64 scopes keep `mode=max` (PR builds and `e2e` lean on their intermediate `uv sync` and `pnpm build` layers), and `deployer` is single-stage, so `mode=max` adds nothing there; (3) the arm64 scopes (`backend-arm64`, `frontend-arm64`, `deployer-arm64`) are written `mode=min`, which stores only the final images' layers (the arm64 PR job is a build check, and publish's arm64 job reuses those final layers); (4) after Task 1's first `main` run the controller measures the cache once and records it. The estimate assumes the default 10 GB cap: GitHub bills cache storage above 10 GB against the same Actions budget, so the cap is not raised; if the owner has already raised it, the measured excess goes into this estimate before `PUBLISH_ON_PUSH` is turned on.
22. **Worker placement: anywhere, with a 1 GiB limit.** Measured while writing this plan: the backend image built natively for `linux/arm64`, run with `--cpus=1 --memory=2g` against `postgres:17`, importing both fixture workbooks (360 events, 7,480 rounds), `rebuild_live`, then `run_pipeline` with a fresh skill calibration over `CALIBRATION_GRID` (27 points), then the whole rebuild job again: peak RSS 101 MiB after migrating, 164 MiB after import + rebuild, **224 MiB** after the pipeline and the recalibration; 3.6 s + 2.7 s + 2.9 s on one Apple-silicon core. The work is single-threaded numpy/pandas, so an RPi4's Cortex-A72 (roughly 5–7× slower per core) needs about 20–45 s per rebuild and an amd64 Proxmox VM core about 2–3× slower than the measurement, 10–20 s. A rebuild runs after an admin commits an import (weekly), in the background, so neither is noticeable. Memory is the real constraint on a 4 GB pico: `limits.memory: 1G` is 4.5× the measured peak (years of history), `reservations.memory: 256M` makes Swarm place it only where that is free. No architecture or node constraint: pinning it to amd64 would buy ~20 s per weekly rebuild at the cost of availability when the VMs are busy, and the worker talks to `db` over the overlay network wherever it runs. `api` and `caddy` are left without limits: `caddy` idles at tens of MiB, and `api` reaches about 110 MiB RSS on arm64 before uvicorn serves anything (importing `sunday_clays.api.app` pulls in numpy and pandas; measured), which a 4 GB Pi holds beside the worker; add limits or a reservation if a Pi ever runs short. Limits need the kernel's memory cgroup: Raspberry Pi kernels have shipped with it off unless `cgroup_enable=memory` is on the kernel command line, and then Docker ignores `limits.memory` with the warning `No memory limit support` (reservations still steer placement). The runbook's check (Task 2) makes sure the 1 GiB worker limit and the deployer's 256 MiB are real.
23. **No architecture constraints at all; hostname pins only for state** (Task 2). Every `sha-<7>` tag from Task 1 on is multi-arch, and `docker stack deploy` / `docker service update` resolve each image in the registry and copy its platforms into the service's placement, so Swarm keeps a task off nodes its image does not support by itself. That copy happens only when the CLI can resolve the image in the registry (`--with-registry-auth` and a working `docker login ghcr.io`); when it cannot, it prints `image … could not be accessed on a registry to record its digest` and deploys with no platform restriction. So the runbook (Tasks 2 and 6) says to stop if a deploy prints that warning, and treats pre-Task-1 tags as unsupported on the mixed fleet; `deployer.py rollback` accepts only tags from its `history`, all multi-arch (Decision 9 gives the other reason). `db` and `backup` keep `node.hostname==${SC_DB_NODE:-autopirate}` (the fleet's single-writer rule), and the checker now also requires both to name the same node. The deployer needs `node.role==manager`, and every schedulable manager is arm64 (`birdo`, optionally `bowser`), so an x86_64 constraint would leave it unschedulable; the runbook's old "check that a manager is x86_64" step is gone. `publish.yml` sets `provenance: false`: with attestations (BuildKit's default; the fleet's imagen notes show the same), each per-arch push is itself an index whose attestation entry carries the platform `unknown/unknown`, and that entry would then sit in the merged list. #!/usr/bin/env python3
```python
"""Fleet rules for the rendered Swarm stack (C11 `stack-config`, amended by Plan 13 for the
multi-arch fleet: Raspberry Pis (arm64) and Proxmox VMs (amd64)).

IMAGE_TAG=sha-0000000 docker stack config -c compose.yaml -c compose.swarm.yaml \
    | uv run --no-project --with pyyaml python scripts/check_stack.py [rendered.yaml]
"""

import re
import sys
from collections.abc import Sequence
from pathlib import Path
from typing import Any

import yaml

REQUIRED_SERVICES = ("caddy", "api", "worker", "db", "backup")
# Single-writer data services: pinned by hostname, all to the same node, one replica each.
PINNED_SERVICES = ("db", "backup")
HOSTNAME = "node.hostname=="
DATA_ROOT = "/var/data/sundayclays/"
# Services that run a release image: CI publishes every sha-<7> tag for linux/amd64 and
# linux/arm64 (publish.yml), so Swarm can place them on any node.
RELEASE_IMAGES = {"caddy": "frontend", "api": "backend", "worker": "backend", "backup": "backend"}
RELEASE_REGISTRY = "ghcr.io/gitgat/sunday-clays-"
RELEASE_TAG = re.compile(r"^sha-[0-9a-f]{7}$")
# node.labels.class (rpi4/rpi5) and node.labels.type (vm/physical) are the fleet's hardware labels:
# a constraint on them pins a service to one architecture just as node.platform.arch does.
ARCH_CONSTRAINT = re.compile(r"^node\.(platform\.arch|labels\.(arch|class|type))(==|!=)")
# Services allowed an architecture constraint. None: every image is multi-arch, and Swarm already
# keeps a task off nodes whose platform its image lacks.
ARCH_PINNED: frozenset[str] = frozenset()


def _constraints(service: dict[str, Any]) -> list[str]:
    placement = (service.get("deploy") or {}).get("placement") or {}
    return [str(c).replace(" ", "") for c in placement.get("constraints") or []]


def _bind_sources(service: dict[str, Any]) -> list[str]:
    sources = []
    for volume in service.get("volumes") or []:
        if isinstance(volume, dict) and volume.get("type") == "bind":
            sources.append(str(volume.get("source", "")))
        elif isinstance(volume, str) and volume.startswith("/"):
            sources.append(volume.split(":", 1)[0])
    return sources


def _release_image_rule(name: str, image: str) -> list[str]:
    kind = RELEASE_IMAGES.get(name)
    if kind is None:
        return []
    repository, _, tag = image.rpartition(":")
    if repository == f"{RELEASE_REGISTRY}{kind}" and RELEASE_TAG.match(tag):
        return []
    return [f"{name}: image must be {RELEASE_REGISTRY}{kind}:sha-<7> (multi-arch), not {image!r}"]


def violations(stack: dict[str, Any]) -> list[str]:
    problems: list[str] = []
    services: dict[str, dict[str, Any]] = stack.get("services") or {}
    for name in REQUIRED_SERVICES:
        if name not in services:
            problems.append(f"{name}: service missing")
    pinned_to: set[str] = set()
    for name, service in sorted(services.items()):
        constraints = _constraints(service)
        if name not in ARCH_PINNED:
            problems += [
                f"{name}: must not be constrained to an architecture ({c}); images are multi-arch"
                for c in constraints
                if ARCH_CONSTRAINT.match(c)
            ]
        image = str(service.get("image", ""))
        if image.endswith(":latest") or ":" not in image.rsplit("/", 1)[-1]:
            problems.append(f"{name}: image {image!r} must carry an explicit tag other than latest")
        problems += _release_image_rule(name, image)
        if name in PINNED_SERVICES:
            hosts = [c for c in constraints if c.startswith(HOSTNAME)]
            if not hosts:
                problems.append(f"{name}: missing {HOSTNAME} placement constraint")
            pinned_to.update(hosts)
            if (service.get("deploy") or {}).get("replicas") != 1:
                problems.append(f"{name}: deploy.replicas must be 1")
            if not any(source.startswith(DATA_ROOT) for source in _bind_sources(service)):
                problems.append(f"{name}: needs a bind mount under {DATA_ROOT}")
    if len(pinned_to) > 1:
        problems.append(f"db and backup must be pinned to one node, not {sorted(pinned_to)}")
    if (services.get("caddy") or {}).get("ports"):
        problems.append("caddy: must not publish ports (Traefik reaches it over traefik_public)")
    for key, secret in sorted((stack.get("secrets") or {}).items()):
        secret_name = str((secret or {}).get("name", ""))
        if not secret_name.startswith("sundayclays_"):
            problems.append(f"secret {key}: name {secret_name!r} must start with sundayclays_")
    return problems


def main(argv: Sequence[str]) -> int:
    text = Path(argv[0]).read_text(encoding="utf-8") if argv else sys.stdin.read()
    stack = yaml.safe_load(text)
    if not isinstance(stack, dict):
        print("check_stack: input is not a rendered stack", file=sys.stderr)
        return 2
    problems = violations(stack)
    for problem in problems:
        print(f"check_stack: {problem}", file=sys.stderr)
    if not problems:
        print(f"check_stack: {len(stack.get('services') or {})} services ok")
    return 1 if problems else 0


if __name__ == "__main__":
    sys.exit(main(sys.argv[1:]))
```

```python
#!/usr/bin/env python3
"""Pull-based image deployer for the sundayclays Swarm stack (Plan 13). Standard library only.

Every POLL_INTERVAL seconds it reads main's SHA with `git ls-remote`. Once CI has published
ghcr.io/gitgat/sunday-clays-{backend,frontend}:sha-<7>, it updates api (and waits until api reports
that version), then worker, caddy and backup, and only then records the SHA in STATE_DIR. A failed
step rolls the services this run already updated back to their previous image, so the stack stays
on one coherent release. While main is unchanged it checks that the services still run the
recorded tag and redeploys it if they drifted. db and the deployer itself are never updated here
(deploy/README.md, "Automatic deploys").

    deployer.py run | once | status | tag | pause [reason...] | resume | rollback sha-<7>
"""

TAG = re.compile(r"^sha-[0-9a-f]{7}$")
SHA = re.compile(r"^[0-9a-f]{40}$")
ABSENT = re.compile(r"no such manifest|manifest unknown|not found", re.IGNORECASE)

class DeployError(Exception):
    """A step failed. Messages never contain a token."""


Run = Callable[..., "subprocess.CompletedProcess[str]"]
Fetch = Callable[[str, float], str]


def run_command(
    argv: Sequence[str],
    *,
    input: str | None = None,
    env: Mapping[str, str] | None = None,
    timeout: float = 60.0,
) -> subprocess.CompletedProcess[str]:
    try:
        return subprocess.run(
            list(argv),
            input=input,
            env=None if env is None else dict(env),
            capture_output=True,
            text=True,
            timeout=timeout,
            check=False,
        )
    except subprocess.TimeoutExpired:
        raise DeployError(f"{' '.join(argv[:3])} timed out after {timeout:.0f}s") from None


def fetch_url(url: str, timeout: float) -> str:
    with urllib.request.urlopen(url, timeout=timeout) as response:  # noqa: S310 (fixed http URL)
        body: bytes = response.read()
    return body.decode("utf-8")


def _log(message: str) -> None:
    print(f"{datetime.now(UTC).isoformat(timespec='seconds')} {message}", flush=True)

    log: Callable[[str], None] = _log

    github_token_file: Path = Path("/run/secrets/deployer_github_token")

    state_dir: Path = Path("/state")
    heartbeat_file: Path = Path("/tmp/deployer-heartbeat")  # noqa: S108 (container-local)
    poll_interval: float = 120.0
    health_url: str = "http://api:8000/api/health"
    health_timeout: float = 600.0
    update_timeout: float = 1200.0

    @classmethod
    def from_env(cls, env: Mapping[str, str]) -> Config:
        d = cls()

            health_timeout = float(env.get("HEALTH_TIMEOUT", d.health_timeout))

        if poll < MIN_POLL_INTERVAL:

        return cls(

            poll_interval=poll,
            health_url=env.get("HEALTH_URL", d.health_url),

def read_secret(path: Path) -> str:
    try:
        value = path.read_text(encoding="utf-8").strip()
    except OSError as exc:
        raise DeployError(f"cannot read secret {path}: {exc.strerror}") from None
    if not value:
        raise DeployError(f"secret {path} is empty")
    return value


def _redact(text: str, *secrets: str) -> str:
    for secret in secrets:
        text = text.replace(secret, "***")
    return text.strip()[-500:]


def tag_for(sha: str) -> str:
    return f"sha-{sha[:7]}"


def image_ref(cfg: Config, kind: str, tag: str) -> str:
    return f"{cfg.registry}/sunday-clays-{kind}:{tag}"


def remote_sha(cfg: Config, deps: Deps) -> str:
    """main's SHA. The token reaches only this git process's environment: no argv, no file."""
    token = read_secret(cfg.github_token_file)
    basic = base64.b64encode(f"x-access-token:{token}".encode()).decode()
    env = {
        **os.environ,
        "GIT_TERMINAL_PROMPT": "0",
        "GIT_CONFIG_COUNT": "1",
        "GIT_CONFIG_KEY_0": "http.extraHeader",
        "GIT_CONFIG_VALUE_0": f"Authorization: Basic {basic}",
    }
    ref = f"refs/heads/{cfg.branch}"
    result = deps.run(["git", "ls-remote", cfg.repo_url, ref], env=env, timeout=60.0)
    if result.returncode != 0:
        detail = _redact(result.stderr, token, basic)
        raise DeployError(f"git ls-remote failed (exit {result.returncode}): {detail}")
    for line in result.stdout.splitlines():
        sha, _, name = line.partition("\t")
        if name == ref and SHA.match(sha):
            return sha
    raise DeployError(f"{ref} not found at {cfg.repo_url}")


def login(cfg: Config, deps: Deps) -> None:
    if not cfg.ghcr_user:
        raise DeployError("GHCR_USER is not set")
    token = read_secret(cfg.ghcr_token_file)
    result = deps.run(
        ["docker", "login", "ghcr.io", "--username", cfg.ghcr_user, "--password-stdin"],
        input=token + "\n",
        timeout=60.0,
    )
    if result.returncode != 0:
        raise DeployError(f"docker login ghcr.io failed: {_redact(result.stderr, token)}")


def missing_images(cfg: Config, tag: str, deps: Deps) -> list[str]:
    """The refs not (yet) in the registry. Any other manifest error is a DeployError."""
    missing = []
    for kind in KINDS:
        ref = image_ref(cfg, kind, tag)
        result = deps.run(["docker", "manifest", "inspect", ref], timeout=60.0)
        if result.returncode == 0:
            continue
        if not ABSENT.search(result.stderr):
            raise DeployError(f"docker manifest inspect {ref} failed: {_redact(result.stderr)}")
        missing.append(ref)
    return missing


def inspect_services(
    cfg: Config, services: Sequence[str], deps: Deps
) -> dict[str, tuple[str, str]]:
    """{service: (spec image without @digest, update state)} from one `docker service inspect`."""
    names = [f"{cfg.stack}_{s}" for s in services]
    label = ", ".join(names)
    result = deps.run(["docker", "service", "inspect", *names], timeout=60.0)
    if result.returncode != 0:
        raise DeployError(f"{label}: docker service inspect failed: {_redact(result.stderr)}")
    try:
        found: dict[str, tuple[str, str]] = {}
        for item in json.loads(result.stdout):
            image = str(item["Spec"]["TaskTemplate"]["ContainerSpec"]["Image"]).split("@", 1)[0]
            state = str((item.get("UpdateStatus") or {}).get("State", "completed"))
            found[str(item["Spec"]["Name"])] = (image, state)
        return {s: found[f"{cfg.stack}_{s}"] for s in services}
    except (ValueError, LookupError, TypeError, AttributeError):
        raise DeployError(f"{label}: unreadable docker service inspect output") from None


def update_service(cfg: Config, service: str, tag: str, deps: Deps) -> bool:
    """Put one service on ``tag``. False when it already runs it (no `service update` at all)."""
    name = f"{cfg.stack}_{service}"
    ref = image_ref(cfg, IMAGE_OF[service], tag)
    current, state = inspect_services(cfg, [service], deps)[service]
    if current == ref and state not in UNSETTLED:
        deps.log(f"deploy {tag}: {name} already on {tag}")
        return False
    deps.log(f"deploy {tag}: updating {name}")
    result = deps.run(
        [
            "docker", "service", "update", "--detach=false", "--quiet",
            "--with-registry-auth", "--image", ref, name,
        ],
        timeout=cfg.update_timeout,
    )  # fmt: skip
    if result.returncode != 0:
        raise DeployError(f"{name}: docker service update failed: {_redact(result.stderr)}")
    current, state = inspect_services(cfg, [service], deps)[service]
    if current != ref or state in UNSETTLED:
        raise DeployError(f"{name}: runs {current} (update state {state}), not {ref}")
    return True


def revert(cfg: Config, services: Sequence[str], deps: Deps) -> list[str]:
    """`docker service rollback` each service (callers pass reverse ORDER); returns those done."""
    done = []
    for service in services:
        name = f"{cfg.stack}_{service}"
        result = deps.run(
            ["docker", "service", "rollback", "--detach=false", "--quiet", name],
            timeout=cfg.update_timeout,
        )
        if result.returncode != 0:
            deps.log(f"{name}: docker service rollback failed: {_redact(result.stderr)}")
            continue
        deps.log(f"rolled back {name} to its previous image")
        done.append(name)
    return done


def wait_for_version(cfg: Config, tag: str, deps: Deps) -> None:
    deadline = deps.clock() + cfg.health_timeout
    last = "no answer"
    while True:
        try:
            body = json.loads(deps.fetch(cfg.health_url, HEALTH_POLL_SECONDS))
            if body.get("status") == "ok" and body.get("version") == tag:
                return
            last = f"version {body.get('version')!r}"
        except (OSError, ValueError, AttributeError) as exc:
            last = type(exc).__name__
        if deps.clock() >= deadline:
            raise DeployError(f"api did not report {tag} within {cfg.health_timeout:.0f}s ({last})")
        deps.sleep(HEALTH_POLL_SECONDS)


def deploy(cfg: Config, tag: str, deps: Deps) -> None:
    """Update the four app services in ORDER. On a failure, roll the ones this run updated back
    (reverse ORDER), so the stack never stays split between two releases. db is never touched."""
    updated: list[str] = []
    try:
        for service in ORDER:
            if update_service(cfg, service, tag, deps):
                updated.append(service)
            if service == "api":
                wait_for_version(cfg, tag, deps)
    except DeployError as exc:
        reverted = revert(cfg, updated[::-1], deps)
        raise DeployError(f"{exc}; rolled back {', '.join(reverted) or 'nothing'}") from None


def load_state(state_dir: Path) -> dict[str, Any]:
    try:
        data = json.loads((state_dir / "state.json").read_text(encoding="utf-8"))
    except (OSError, ValueError):
        return {}
    return data if isinstance(data, dict) else {}


def save_state(state_dir: Path, state: dict[str, Any]) -> None:
    state_dir.mkdir(parents=True, exist_ok=True)
    tmp = state_dir / "state.json.tmp"
    tmp.write_text(json.dumps(state, indent=2, sort_keys=True) + "\n", encoding="utf-8")
    os.replace(tmp, state_dir / "state.json")


def record(state_dir: Path, *, sha: str, tag: str, when: datetime, how: str) -> None:
    state = load_state(state_dir)
    entry = {"sha": sha, "tag": tag, "at": when.isoformat(timespec="seconds"), "how": how}
    state.update(sha=sha, tag=tag, deployed_at=entry["at"])
    state["history"] = [entry, *state.get("history", [])][:HISTORY]
    save_state(state_dir, state)


def note_failure(state_dir: Path, *, sha: str, tag: str, reason: str, when: datetime) -> None:
    """For `status` only. Never touches sha/tag: a failed deploy records nothing as deployed."""
    state = load_state(state_dir)
    at = when.isoformat(timespec="seconds")
    state["last_failure"] = {"sha": sha, "tag": tag, "at": at, "reason": reason}
    save_state(state_dir, state)


def set_paused(state_dir: Path, reason: str | None) -> None:
    state = load_state(state_dir)
    if reason is None:
        state.pop("paused", None)
    else:
        state["paused"] = reason
    save_state(state_dir, state)


@contextmanager
def deploy_lock(state_dir: Path) -> Iterator[None]:
    """Serialises the poll loop and a `docker exec … rollback` in the same container."""
    state_dir.mkdir(parents=True, exist_ok=True)
    with (state_dir / "deploy.lock").open("w") as handle:
        fcntl.flock(handle, fcntl.LOCK_EX)
        try:
            yield
        finally:
            fcntl.flock(handle, fcntl.LOCK_UN)


def drifted(cfg: Config, tag: str, deps: Deps) -> list[str]:
    """Settled app services whose spec image is not ``tag`` (a hand deploy, a later Swarm
    rollback): the recorded state no longer describes what runs."""
    return [
        f"{cfg.stack}_{service} runs {image}"
        for service, (image, state) in inspect_services(cfg, ORDER, deps).items()
        if image != image_ref(cfg, IMAGE_OF[service], tag) and state not in UNSETTLED
    ]


def _roll_out(cfg: Config, deps: Deps, sha: str, tag: str, failed: set[str], how: str) -> str:
    try:
        deploy(cfg, tag, deps)
    except DeployError as exc:
        failed.add(sha)
        note_failure(cfg.state_dir, sha=sha, tag=tag, reason=str(exc), when=deps.now())
        deps.log(
            f"deploy {tag} FAILED: {exc}. The deployed release is unchanged; {tag} is not retried"
            " until main moves or the deployer restarts."
        )
        return "failed"
    record(cfg.state_dir, sha=sha, tag=tag, when=deps.now(), how=how)
    deps.log(f"deploy {tag}: done")
    return "deployed"


def tick(cfg: Config, deps: Deps, failed: set[str], waiting: set[str] | None = None) -> str:
    """One poll. Returns paused | unchanged | failed-before | waiting | failed | deployed.

    ``failed`` and ``waiting`` live as long as the loop: a failed SHA is not retried, and
    "waiting for" is logged once per SHA."""
    waiting = set() if waiting is None else waiting
    with deploy_lock(cfg.state_dir):
        state = load_state(cfg.state_dir)
        if state.get("paused"):
            return "paused"
        sha = remote_sha(cfg, deps)
        if sha in failed:
            return "failed-before"
        if sha == state.get("sha"):
            tag = str(state.get("tag", ""))
            drift = drifted(cfg, tag, deps)
            if not drift:
                return "unchanged"
            deps.log(f"drift: {'; '.join(drift)}; recorded {tag}, redeploying it")
            login(cfg, deps)
            return _roll_out(cfg, deps, sha, tag, failed, how="drift")
        tag = tag_for(sha)
        login(cfg, deps)
        missing = missing_images(cfg, tag, deps)
        if missing:
            if sha not in waiting:
                deps.log(f"{tag}: waiting for {', '.join(missing)}")
                waiting.add(sha)
            return "waiting"
        return _roll_out(cfg, deps, sha, tag, failed, how="auto")


def rollback(cfg: Config, deps: Deps, tag: str) -> None:
    """Deploy an older sha-<7> in the same order and pause automatic deploys."""
    if not TAG.match(tag):
        raise DeployError(f"{tag!r} is not a sha-<7> tag")
    with deploy_lock(cfg.state_dir):
        login(cfg, deps)
        missing = missing_images(cfg, tag, deps)
        if missing:
            raise DeployError(f"{tag}: not in the registry: {', '.join(missing)}")
        set_paused(
            cfg.state_dir, f"rollback to {tag} at {deps.now().isoformat(timespec='seconds')}"
        )
        deploy(cfg, tag, deps)
        record(cfg.state_dir, sha="", tag=tag, when=deps.now(), how="rollback")
    deps.log(f"rolled back to {tag}; automatic deploys stay paused until `deployer.py resume`")


def recorded_tag(state_dir: Path) -> str:
    """The live release as recorded: what a hand `docker stack deploy` must use as IMAGE_TAG."""
    tag = str(load_state(state_dir).get("tag", ""))
    if not TAG.match(tag):
        raise DeployError("no deploy recorded (state is empty); read the tag from /api/health")
    return tag


def serve(cfg: Config, deps: Deps, stopping: Callable[[], bool]) -> int:
    deps.log(f"deployer: watching {cfg.repo_url} {cfg.branch} every {cfg.poll_interval:.0f}s")
    failed: set[str] = set()
    waiting: set[str] = set()
    while not stopping():
        cfg.heartbeat_file.touch()  # before the poll: a deploy can take far longer than one
        try:
            tick(cfg, deps, failed, waiting)
        except DeployError as exc:
            deps.log(f"poll failed: {exc}")
        waited = 0.0
        while waited < cfg.poll_interval and not stopping():
            deps.sleep(1.0)
            waited += 1.0
    deps.log("deployer: stopped")
    return 0


def main(argv: Sequence[str], env: Mapping[str, str] = os.environ, deps: Deps | None = None) -> int:
    parser = argparse.ArgumentParser(prog="deployer.py", description=__doc__.splitlines()[0])
    commands = parser.add_subparsers(dest="command", required=True)
    commands.add_parser("run", help="poll and deploy until SIGTERM")
    commands.add_parser("once", help="one poll, then exit")
    commands.add_parser("status", help="print the recorded state as JSON")
    commands.add_parser("tag", help="print the recorded live tag (for a hand stack deploy)")
    pause = commands.add_parser("pause", help="stop automatic deploys")
    pause.add_argument("reason", nargs="*")
    commands.add_parser("resume", help="resume automatic deploys")
    back = commands.add_parser("rollback", help="deploy an older sha-<7> and pause")
    back.add_argument("tag")
    args = parser.parse_args(argv)
    deps = deps or Deps()
    try:
        cfg = Config.from_env(env)
        if args.command == "run":
            stop: list[bool] = []

            def on_term(_signum: int, _frame: FrameType | None) -> None:
                stop.append(True)

            signal.signal(signal.SIGTERM, on_term)
            return serve(cfg, deps, lambda: bool(stop))
        if args.command == "once":
            print(tick(cfg, deps, set()))
        elif args.command == "status":
            print(json.dumps(load_state(cfg.state_dir), indent=2, sort_keys=True))
        elif args.command == "tag":
            print(recorded_tag(cfg.state_dir))
        elif args.command == "pause":
            with deploy_lock(cfg.state_dir):
                set_paused(cfg.state_dir, " ".join(args.reason) or "paused by hand")
        elif args.command == "resume":
            with deploy_lock(cfg.state_dir):
                set_paused(cfg.state_dir, None)
        else:
            rollback(cfg, deps, args.tag)
    except DeployError as exc:
        print(f"deployer: {exc}", file=sys.stderr)
        return 1
    return 0


if __name__ == "__main__":
    sys.exit(main(sys.argv[1:]))
```

```python
def _exposes_the_socket(source: str) -> bool:
    """The socket itself, or a directory that holds it (`/`, `/run`, `/var/run`, `/var`)."""
    directory = source.rstrip("/")
    return not directory or any(
        s == directory or s.startswith(directory + "/") for s in DOCKER_SOCKETS
    )


def _socket_and_manager_rules(
    name: str, service: dict[str, Any], constraints: list[str]
) -> list[str]:
    """Only the deployer may hold the Docker socket, and it runs as one task on a manager."""
    binds = _bind_sources(service)
    problems: list[str] = []
    if name != DEPLOYER:
        problems += [
            f"{name}: only {DEPLOYER} may mount {s}" for s in binds if _exposes_the_socket(s)
        ]
        if MANAGER in constraints:
            problems.append(f"{name}: only {DEPLOYER} may be placed with {MANAGER}")
        return problems
    if MANAGER not in constraints:
        problems.append(f"{name}: missing placement constraint {MANAGER}")
    if (service.get("deploy") or {}).get("replicas") != 1:
        problems.append(f"{name}: deploy.replicas must be 1")
    if DOCKER_SOCKETS[0] not in binds:
        problems.append(f"{name}: needs a bind mount of {DOCKER_SOCKETS[0]}")
    problems += [
        f"{name}: bind mount {s!r} is not allowed (only {DOCKER_SOCKETS[0]})"
        for s in binds
        if s != DOCKER_SOCKETS[0]
    ]
    if service.get("ports"):
        problems.append(f"{name}: must not publish ports")
    return problems
```

````markdown
off for good). On the manager the deployer runs on (`docker service ps sundayclays_deployer`), in
the directory holding `compose*.yaml` and `secrets/`, run these lines one at a time:

```bash
export GHCR_USER=<github-login>    # owner of the read:packages token ("Automatic deploys" → "Tokens")
D=$(docker ps -q -f name=sundayclays_deployer)
docker exec "$D" python3 /app/deployer.py pause "stack deploy"   # waits for a rollout in progress
export IMAGE_TAG=$(docker exec "$D" python3 /app/deployer.py tag)
[[ $IMAGE_TAG =~ ^sha-[0-9a-f]{7}$ ]] && echo "deploy $IMAGE_TAG" || echo "STOP: bad tag '$IMAGE_TAG'"
docker stack deploy --with-registry-auth -c compose.yaml -c compose.swarm.yaml sundayclays
D=$(docker ps -q -f name=sundayclays_deployer)   # the deployer may have been recreated
docker exec "$D" python3 /app/deployer.py resume
curl -fsS https://sundayclays.claysmasher.com/api/health   # {"status":"ok","version":"sha-<7>"}
```

- Do not run `docker stack deploy` if the check printed `STOP`. `deployer.py tag` fails with
  `no deploy recorded` only when the deployer's state is empty (a fresh volume, or the task moved
  to another manager); then use the `version` that `/api/health` reports, which is the live
  release because a failed rollout is always rolled back as a whole.
- Never take `IMAGE_TAG` from an old command line or from a single service's image: an older tag
  makes the deployer see drift and put the recorded release straight back after `resume`.
- `api` runs `alembic upgrade head` before uvicorn. Every service updates stop-first (Swarm's
  default; `worker`, `db` and `backup` also set it), so an old and a new `api` never run together
  and the site is briefly down while the new `api` migrates and starts.
- Services update independently, so the previous release's `worker` can still run against the
  migrated schema until its own update; expand/contract migrations keep that safe.
- `api`, `worker`, `caddy` and `backup` roll back by themselves (`failure_action: rollback`): a new
  task that never turns healthy, or fails within 60 s of starting, puts that service back on its
  previous image. `db` never rolls back automatically.
- `worker`, `db` and `backup` run one replica each; the worker gets 5 minutes to finish its current
  job.
- `IMAGE_TAG` and `GHCR_USER` are required (`${…:?}`); `latest` is never deployed. The tag must
  also have a `sunday-clays-deployer` image, which every tag published after Plan 13 has; to go
  back to an older release, use `deployer.py rollback` ("Rollback"), which never touches the
  deployer.
- If `docker stack deploy` prints `could not be accessed on a registry to record its digest`, stop
  and fix `docker login ghcr.io`: without the registry, Swarm gets no platform list and may put an
  image on a node of the wrong architecture. Tags published before Plan 13 are amd64-only and are
  not supported on this fleet ("Preconditions").

## Automatic deploys

The `deployer` service (`deploy/deployer/deployer.py`, one task on a Swarm manager) asks GitHub for
`main`'s SHA every 2 minutes (`git ls-remote`). When `main` has moved and CI has published both
`sunday-clays-backend:sha-<7>` and `sunday-clays-frontend:sha-<7>` (the `publish` job runs only
after `ci-ok` passes on `main`), it runs `docker service update --with-registry-auth --image …:sha-<7>`
on `api`, waits until `/api/health` reports `sha-<7>`, then updates `worker`, `caddy` and `backup`,
and records the SHA in its `deployer-state` volume. A service already on that image is skipped.

- It never touches `db`, and it never updates itself: a process cannot supervise its own
  replacement. A hand `docker stack deploy` (above) refreshes it.
- A failed step stops the rollout. Swarm has already rolled the failed service back; the deployer
  then rolls back the services it had already updated (`worker`, then `api`), so the whole stack is
  on the previous release again, and leaves the later services alone. Nothing is recorded as
  deployed (`status` shows it under `last_failure`), and that SHA is not tried again until `main`
  moves or the deployer restarts.
- While `main` is unchanged it checks, every poll, that the four services still run the recorded
  tag. If one does not (a hand deploy with an old tag, a later Swarm rollback), it logs `drift: …`
  and redeploys the recorded tag. A paused deployer does not check.
- Every image is published for `linux/amd64` and `linux/arm64`, and a `sha-<7>` tag appears only
  once both architectures are pushed. The `publish` run tags the deployer image first and the
  backend/frontend pair last, so a publish run whose deployer build breaks, on either
  architecture, deploys nothing. CI's `docker` and `docker-arm64` jobs build the deployer image on
  every PR, so that should not reach `main`.
- The deployer holds the Docker socket, which means root on that manager. It is the only service
  allowed to (`scripts/check_stack.py`).

### Tokens

1. **GitHub token** (for `git ls-remote`): a fine-grained personal access token with resource owner
   `gitgat` (a user account, so the token is created while signed in as `gitgat`), access to the
   repository `gitgat/sunday-clays` only, and permission Contents: Read-only (GitHub adds
   Metadata: Read-only). Nothing else. Note its expiry date.
2. **GHCR token** (for pulls): a classic personal access token with only `read:packages` (GHCR does
   not take fine-grained tokens). The one from "One-time setup" step 1 can be reused. A classic
   token can read every package its owner can see, so prefer one owned by a dedicated machine
   account that is a collaborator on `gitgat/sunday-clays` with read access only (the packages
   inherit the repository's access).
3. On the manager, next to the other secret files:

   ```bash
   read -rsp 'GitHub contents:read token: ' t && echo && printf '%s\n' "$t" > secrets/deployer_github_token
   read -rsp 'GHCR read:packages token: ' t && echo && printf '%s\n' "$t" > secrets/deployer_ghcr_token
   unset t && chmod 600 secrets/deployer_*
   ```

To rotate a token, write the new value into its file, then run the "Deploy or upgrade" sequence
with `export DEPLOYER_SECRETS_REV=2` (then 3, and so on) before `docker stack deploy`. This counter
is separate from `SECRETS_REV`, so the app's six secrets stay put. Afterwards remove the old
versions with
`docker secret ls --format '{{.Name}}' | grep -E '^sundayclays_deployer_.+_v1$' | xargs -r docker secret rm`.
An expired or wrong token shows in the logs as `poll failed: git ls-remote failed (exit 128)` or
`poll failed: docker login ghcr.io failed`.

### Turn it on (first deploy)

The deployer runs on any Swarm manager, Raspberry Pi (`birdo`) or VM: its image, like the app
images, is published for both `linux/arm64` and `linux/amd64`.

1. With the owner's OK, publish from every CI-green `main` commit:
   `gh variable set PUBLISH_ON_PUSH --body true --repo gitgat/sunday-clays`. Each merge to `main`
   then also runs the `publish` jobs (one cached build per image and architecture, then a merge;
   a few Actions minutes).
2. Wait for the `publish` run of the newest `main` commit, then deploy its tag once by hand (there
   is no deployer to pause yet):
   `export GHCR_USER=<github-login>` and
   `IMAGE_TAG=sha-<7> docker stack deploy --with-registry-auth -c compose.yaml -c compose.swarm.yaml sundayclays`.
3. `docker service logs -f sundayclays_deployer` shows `deployer: watching … main every 120s`.
   From then on, a merge to `main` is live a few minutes after its `publish` run finishes.

Every automatic deploy restarts `worker` (it gets 5 minutes to finish its job), `caddy` (a few
seconds of errors) and `backup` (which takes a fresh dump on start). Pause around club shoots:
`deployer.py pause "club shoot"`, then `resume` afterwards.

### Talking to it

`docker service ps sundayclays_deployer` shows the manager it runs on. Run these on that node:

```bash

(without updating anything when that is already live) and forgets a pause, so pause again after a
failover.

### Rollback

- **Automatic:** see above. Check `docker service ps sundayclays_<service>` for the failed task,
  `deployer.py status` for `last_failure`, and `docker service logs sundayclays_deployer` for
  `deploy sha-<7> FAILED: …`.
- **Manual, to an earlier release:**

  ```bash
  docker exec "$D" python3 /app/deployer.py status               # history lists earlier tags
  docker exec "$D" python3 /app/deployer.py rollback sha-<7>
  ```

  This updates `api`, `worker`, `caddy` and `backup` in the usual order (skipping any already on
  that tag) and **pauses** automatic deploys, because otherwise the next poll would put `main`
  straight back. Once `main` has the fix, run `resume`. Roll back only to a tag in the `history`,
  for two reasons: those were all built after the rollback-safe start-up (Plan 13 Task 3), and an
  older image crashes on a migrated database with `Can't locate revision`; and they are all
  multi-arch, while older tags are amd64-only and can land on a Pi if Swarm cannot read their
  platforms ("Preconditions").
- **Retry a failed SHA** without a new commit: `docker service update --force sundayclays_deployer`.
- **Without the deployer** (if it is itself broken): stop it with
  `docker service scale sundayclays_deployer=0` (a later `docker stack deploy` sets it back to 1),
  then on a manager run the loop below. It goes in the same order as the deployer and stops at
  the first failure; if it stops, run it again with the previous tag so the stack is not left
  split between two releases.

  ```bash
  TAG=sha-<7>   # a tag from the deployer's history; stop if an update prints "could not be accessed"
  for s in api worker caddy backup; do
    kind=backend; [ "$s" = caddy ] && kind=frontend
    docker service update --with-registry-auth --image "ghcr.io/gitgat/sunday-clays-$kind:$TAG" \
      "sundayclays_$s" || { echo "stopped at $s"; break; }
  done
  ```

  When the deployer comes back, it compares the services with its recorded tag and puts that
  release back ("drift"). Before scaling it up, either `pause` it first or make sure `main` has
  the release you want.
- **The schema:** the previous release runs on the newer schema, because migrations are
  expand/contract. Its `api` logs `database schema is newer than this image's migrations (a
  rollback); starting without migrating (database at …, image head …)` and starts, and its
  `worker` accepts the schema too. Rolling back further than one release is safe only if no
  migration in between removed or renamed something the older code uses. Otherwise restore a
  backup ("Backups and restore").

### Logs

`docker service logs -f --since 1h sundayclays_deployer`:

- `deploy sha-<7>: updating sundayclays_<service>` … `deploy sha-<7>: done`: a rollout
  (`… already on sha-<7>` for a service that needed nothing).
- `sha-<7>: waiting for …`: CI has not finished publishing that commit (or it failed CI). Logged
  once per commit.
- `deploy sha-<7> FAILED: …; rolled back …`: stopped, and the services it had updated are back on
  the previous release. Nothing recorded as deployed; see "Rollback".
- `drift: sundayclays_<service> runs …; recorded sha-<7>, redeploying it`: something other than the
  deployer changed a service's image.
- `poll failed: …`: GitHub or GHCR unreachable, or a token is wrong or expired.
- No lines at all between deploys is normal: an unchanged `main` is silent.
````

**How the fleet's public edge works** (read from `../swarm-config`, verify there before writing anything): visitor → Cloudflare (TLS, WAF) → Cloudflare Tunnel → `cloudflared` service (`cloudflared/config.yml` ingress, one `hostname:` → `service: http://traefik-public:80` pair per public host) → `traefik-public` (file-provider only, `traefik-public/dynamic/routes.yml`, plain `web` :80, network `edge_public`, no host ports) → the app's service on `edge_public`. `gitgat` and `sarahpletcher.art` follow this pattern. The master plan assumed Traefik host ports were the public edge; that assumption is replaced by this task.

**Client IP on each path:**
- **Tunnel path.** The peer Caddy sees is `traefik-public` (an overlay address in `private_ranges`).
