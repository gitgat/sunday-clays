# Sunday Clays Implementation Plan (Master)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> Each sub-plan (`docs/superpowers/plans/2026-09-27-NN-*.md`) is executed the same way; tasks in the same wave with
> disjoint files run in parallel, each in its own git worktree + PR, merged only when CI is green (Plan 01 T1–T4
> excepted, see §0 step 4a). Dependency chains are shipped as **GitHub stacked PRs** (`gh stack`, §0 step 5): a task
> starts as soon as the task below it passes task review, without waiting for that task to merge.
> **Every subagent and workflow agent runs on Opus** (overrides the SDD skill's cheaper-model guidance).

**Goal:** Ship sundayclays.claysmasher.com — versioned xlsx ingest with rollback, two-password access, and a deep,
explorable analytics app (mobile + desktop) for the Sunday Clays group.

**Architecture:** Python/FastAPI API + Postgres-queue worker over a Postgres 17 DB whose "live" tables are always
*rebuilt* from immutable imports + overlay rules; analytics are pure pandas/numpy functions run as ordered
recompute steps and cached by `data_version`; a React/Vite SPA with Apache ECharts served by Caddy.
Extension points (API routers, recompute steps, achievement modules, frontend routes, profile/event sections, home
widgets) are auto-discovered so
parallel tasks never edit the same registry file.

**Tech Stack:** Python 3.13 · uv · FastAPI + uvicorn + python-multipart · SQLAlchemy 2 · Alembic · Pydantic v2 +
pydantic-settings · psycopg 3 · openpyxl + defusedxml · pandas · numpy · scipy · httpx · argon2-cffi · itsdangerous ·
tzdata · pytest/pytest-cov/respx/testcontainers/hypothesis · Node 22 · pnpm · React 19 · Vite · TypeScript (strict) ·
Tailwind v4 · ECharts · TanStack Query v5 · React Router v7 · openapi-typescript + openapi-fetch · html-to-image ·
@fontsource/roboto · lucide-react · Vitest + Testing Library + MSW · Playwright · Caddy 2 · Postgres 17 · Docker Compose ·
GitHub Actions · GHCR · lefthook. Exact package lists: Plan 01 T1 (backend) and T2 (frontend).

## Review Focus
1. **Stale or partial scores file uploaded** (older copy missing recent weeks) → preview must list removed events/rows prominently and `commit` must refuse unless `confirm_removals=true`. Owner: Plan 03 Task 6 (test `test_commit_refuses_unconfirmed_removals`) and Plan 08 Task 5a (Vitest `commit stays disabled until removals are confirmed`).
2. **Station-sheet names that don't match the scores file** (NBSP, typo, person absent from scores) → looked up via `lookup_shooter` on the same identity key (never creates a shooter); unmatched → `data_issues` row `station_name_unmatched` plus a preview WARNING finding, never a crash; admin fixes it with an `alias_name` rule. Owner: Plan 03 Task 4 (test `test_unmatched_station_name_becomes_issue`, asserts no shooter row is created) and Plan 03 Task 3 (preview).
3. **Excel quirks** — formulas with no cached values (file written by a script such as openpyxl; Excel, LibreOffice and Google Sheets write cached values), dates stored as strings or serials, trailing blank rows, tab name disagreeing with A2, a non-workbook or unrelated workbook → parser recomputes station totals, evaluates `=A{r-1}+N` attendance dates, and reports any other uncached formula in a read cell as a finding (ERROR with the row excluded, never silently dropped; in Status or Class a WARNING with the field left blank), coerces dates, skips blanks, trusts A2 (finding `sheet_name_date_mismatch`), and raises `ParseError` with a human message for unusable files (API → 400). Owner: Plan 02 Tasks 2–4 (tests `test_unusable_file_raises_parse_error` (T2), `test_attendance_date_formulas_evaluated` and `test_uncached_formula_is_error_finding` (T3), `test_tab_name_a2_mismatch_trusts_a2` (T4); synthetic workbooks built with openpyxl in `tests/unit/ingest/builders*.py`).
4. **Ties and multi-round days** in ranks, leaderboards, season points and achievements → shared "min" rank, best-round rule (exactly one best round per (event_date, shooter_id), also across merged aliases), deterministic ordering (score desc, then name_key, then ordinal). Owner: Plan 06 Task 2 (`test_ties_share_min_rank`, `test_best_round_used_for_rank`, `test_merged_aliases_same_day_single_best_round`) and Plan 09 Task 2 (`test_tied_finish_shares_points`).
5. **Rolling back an import that is not the newest** (e.g., rollback stations v1 after v2 committed; rollback scores v2 when v3 exists) → allowed; live state = rebuild from the remaining committed imports; station week reverts to next-newest source or disappears. Owner: Plan 03 Task 6 (`test_rollback_middle_station_import`, `test_rollback_non_latest_scores_import_keeps_latest_active`).

When a task passes task review, the controller runs `gh stack add task/03-2-<slug>` from the top of the stack and creates the next worktree; the next implementer starts immediately, on top of reviewed but unmerged work.
  - **Siblings.** Same-wave siblings on the same parent that touch disjoint files (e.g. Plan 02 T3 ∥ T4) are implemented concurrently on branches cut from the parent layer. They are then linearized into the stack in plan order (`gh stack add` for the first; `git rebase --onto <first> <parent> <second>` then `gh stack init`/`add` to adopt the second — disjoint files guarantee no conflicts). Chains with no shared ancestry beyond `main` are separate stacks.
  - **Publish.** `gh stack submit --auto` after each new layer (PRs open as drafts; drafts still run CI); `gh stack submit --auto --open` once the whole chain has passed task review.
  - **Fixes to a lower layer** (review fix round or CI failure): the implementer commits on its own layer branch; the controller then runs `gh stack rebase --upstack` from that layer and `gh stack push`. On exit 3 the controller dispatches the implementer of the first conflicted upper layer to resolve in its worktree, `git add`, `gh stack rebase --continue`; then `gh stack push`. Generated API files are gitignored (C1) and `ratchets/` is controller-only (C11), so conflicts are only ever in hand-written files.
  - **Land.** When every layer's `ci-ok` is green (`gh pr checks <N> --required --watch` for each layer), the controller runs `gh stack merge <stack-number> --squash --yes` (bottom-up; lands the whole stack), then `gh stack sync --prune` and `git worktree remove` for each layer. Only one stack merges at a time; after each merge the controller runs `gh stack sync` on every other open stack (rebases onto the new `main`; CI re-runs), resolving exit-3 conflicts as above.
  - **Cancelled duplicate runs.** When a push fires duplicate `pull_request` runs for one PR, the concurrency group cancels one of them, and the cancelled run's `ci-ok` records `failure` on the same head SHA; that check blocks `gh stack merge` even after the newer run passes. Re-run the cancelled run (`gh run rerun <id>`) and wait for it to go green before merging.
  - **One-task chains:** GitHub links only two or more PRs as a stack, so `gh stack merge` rejects a single-PR stack; land it with `gh pr merge <N> --squash --match-head-commit <sha>` (or `--auto` once branch protection is on), then `gh stack unstack --local`.
  - **Partial landing** is allowed when a lower prefix is complete and green but an upper layer is still in review: `gh stack merge <pr-number-of-last-ready-layer> --squash --yes` lands that layer and everything below it; the rest re-target `main` automatically.
  - If CI on `main` goes red, stop all merges until it is fixed.
  - **Plan context for every dispatch.** Before the first task of plan P, the controller writes `$(bash <sdd>/scripts/sdd-workspace P)/plan-context.md` with `awk '/^```/{f=!f} !f && (/^## Controller follow-up/ || /^#+[ \t]+Task[ \t]+[0-9]+/){exit} {print}' P` — the plan header (Global Constraints, Review Focus, Decisions, File Structure, Waves), stopping before Plan 01's controller-only section, which must never reach an implementer. Every implementer, fix-round and task-reviewer dispatch names that file next to `task-N-brief.md` and states: "Read plan-context.md first; every Global Constraint applies to this task, and every 'Decision Dn' / 'Review Focus #n' reference in the brief is defined there. The master plan (docs/superpowers/plans/2026-09-27-00-master.md) defines C1–C12."

### C2. Backend conventions
- `config.Settings` (pydantic-settings): `database_url`, `session_secret`, `viewer_password_hash`, `admin_password_hash`, `club_lat` (default `45.3525`, set and verified in Plan 05 Task 1; it replaced `45.3565`), `club_lon` (default `-122.8082`, same; it replaced `-122.8228`), `timezone="America/Los_Angeles"`, `max_upload_bytes=10_485_760`, `open_meteo_archive_url`, `open_meteo_forecast_url`, `app_version`, `weather_enabled: bool = True` (false → `weather_sync`/`forecast_refresh` handlers and the scheduler are successful no-ops; compose.test.yaml sets `WEATHER_ENABLED=false`), `login_max_failures: int = 10`, `login_window_minutes: int = 15`, `cookie_secure: bool = True` (compose.test.yaml and compose.override.yaml set `COOKIE_SECURE=false`, because CI e2e and local compose run over plain http on :8080). No other flags: calibration is controlled by `app_state.skill_params` (C7), not a setting. Secret fields (`SecretStr`, each also read from `<NAME>_FILE`, file contents stripped): `database_url`, `session_secret`, `viewer_password_hash`, `admin_password_hash` — implemented once in `config.py` and tested. Setting both X and X_FILE, or X_FILE pointing to a missing or empty file, is a startup error naming the variable and path, never the value. `viewer_password_hash`/`admin_password_hash` must start with `$argon2id$`; `session_secret` must be ≥32 bytes. No secret has a default. Plan 01 T1 implements every C2 field; Plan 05 T1 may change only the `club_lat`/`club_lon` default values; any other new field needs a C2 amendment and belongs to exactly one task. `config.database_url_from_env()` reads only `DATABASE_URL`/`DATABASE_URL_FILE` (used by `migrations/env.py`). - **Rebuild**: `rebuild_live` holds `pg_advisory_xact_lock(7263003)` and clears the live tables with DELETE in FK order (children first), so readers keep their MVCC snapshot and never wait on a rebuild. Ids are not reset: live ids (`rounds.id`, `station_hits.id`, …) are not stable across rebuilds.
- **Rule targeting**: at rebuild a `score_override`/`hide_round` rule is skipped if no staged row matches (event_date, name_key, ordinal) with that `raw_score`; a skipped rule emits `data_issues` code `rule_target_missing` (warning, details include `rule_id`) and never moves to another round. Rebuild also emits INFO issue `merged_same_day_rounds` when ≥2 name_keys of one shooter have rounds on the same date.
- **Station identity**: only score rows call `resolve_shooter`. Station rows call `lookup_shooter(identity_key(name_key, event_date))`, after active `alias_name` rules are applied. On a miss: `shooter_id` NULL, `round_id` NULL, issue `station_name_unmatched` (details: name_key, raw_name, event_date).
- **Station→round link** (`link_station_entries`), for each (event_date, shooter_id):
  - Pass 1: take entries in order of recomputed total desc, then entry_row; link each to the lowest-ordinal unused round with score == total.
  - Pass 2: pair the remaining entries with the remaining unused rounds, in ordinal order.
  - A round is never linked twice. An entry with no round left gets `round_id` NULL and `station_score_missing`. Any linked entry whose total ≠ score gets `station_score_mismatch`. `station_round_ambiguous` only when the shooter has ≥2 rounds that day and the entry was linked in Pass 2.
  - Fixture: Hadley, Ike 2026-09-13 yields exactly one issue, `station_score_mismatch` (36 vs 34), and no ambiguity issue.
- **Preview** (satisfies spec §2 without new diff types; Plan 03 T3): `stage_import` runs `link_station_entries` against live data — a stations import links its staged sheets against live rounds; a scores import links its staged score rows against live `station_hits` — and appends the resulting issues to `ImportPreview.findings` as WARNING Findings with codes `station_score_mismatch`, `station_name_unmatched` and `station_round_ambiguous`, filling event_date and name.

### C6. Jobs & pipeline (Plan 03 Task 7)
- Ownership: the `rebuild` handler is owned by Plan 03 T4 (`jobs/rebuild_handler.py`); the `jobs/worker.py` CLI stub by Plan 01 T1; all other C6 items (incl. both scheduler entries) by Plan 03 T7.
- `jobs/queue.py`:
  - `enqueue(session, kind: str, payload: dict | None = None, *, run_after: datetime | None = None, dedupe_key: str | None = None) -> int`: `INSERT … ON CONFLICT (dedupe_key) WHERE status = 'queued' DO NOTHING RETURNING id`; no row back → `SELECT id FROM jobs WHERE dedupe_key = :k AND status = 'queued'`; also empty (just claimed) → retry the INSERT once. Never raises on a duplicate and never aborts the caller's transaction; a no-op on conflict returns the existing (coalesced) job id, which the API returns.
  - Fixed dedupe keys: `rebuild` (commit, rollback, every rule create/deactivate, shooter merge/rename/status/alias), `recompute`, `weather_sync` (shared by the rebuild handler and the scheduler), `forecast_refresh`.
  - `claim_next(session) -> Job | None` (`FOR UPDATE SKIP LOCKED`, oldest `run_after`): in its own committed transaction sets `status='running'`, `started_at=now()`, `attempts=attempts+1`; the handler then runs in a separate transaction.
  - `complete(session, job_id)`; `get_job(session, job_id) -> JobOut`.
  - `fail(session, job_id, error)`: requeue with backoff (1m, then 5m) while `attempts < 3`, else `status='failed'`; if a queued job with the same `dedupe_key` already exists, set `status='failed'`, `error='superseded by job <id>'` instead of requeuing.
- `jobs/handlers.py`: `HANDLERS: dict[str, Callable[[Session, dict], None]]` populated by `@handler("kind")` decorators in modules auto-imported from `sunday_clays.jobs` + `sunday_clays.weather`; job kinds: `rebuild` (rebuild_live → run_pipeline → enqueue `weather_sync` for events lacking weather), `recompute` (if `payload.get('recalibrate')` is true, delete app_state key `skill_params` first, so s30 recalibrates over `CALIBRATION_GRID` (C7); then run_pipeline — `RecomputeStep.run(session)` is unchanged), `weather_sync` (upsert `weather_hourly`, updating an existing row only when its values or `source` are `IS DISTINCT FROM` the fetched ones; if any inserted or changed row falls inside an event window, enqueue `recompute` with `dedupe_key='recompute'` — a no-op returning the existing id when one is already queued), `forecast_refresh`. The worker marks a job whose kind has no registered handler `failed` with error `no_handler` and does not retry it. When `weather_enabled` is false, `weather_sync`/`forecast_refresh` complete as no-ops.
- `jobs/worker.py`: `run_worker(stop: threading.Event, poll_seconds=2.0)`; entrypoint `python -m sunday_clays.jobs.worker`. **Worker-health contract** (Plan 01 T1 stub, kept by Plan 03 T7): on start wait until `db.schema_is_current` (poll 2 s, time out after 180 s → exit 1); touch `/tmp/worker-heartbeat` on every poll, before and after the schema is current, and, while a job runs, from a heartbeat thread at least every 10 s (compose healthcheck: mtime < 60 s); that thread stops after 30 minutes, so a job running longer is treated as hung and the heartbeat goes stale; exit cleanly on SIGTERM/SIGINT.
  - Single-worker invariant: exactly one worker process, running one job at a time (compose `replicas: 1`, `update_config.order: stop-first`, `stop_grace_period: 5m`; Plan 01 T4).
  - Startup recovery: before the first poll, `recover_orphans(session)` sends every `running` job through `fail()`'s requeue/fail/superseded logic with `error='worker restarted'`.
  - SIGTERM/SIGINT set `stop`; the loop finishes the current job, then exits.
- `jobs/scheduler.py`: no in-memory timers. On each worker poll `schedule_due(session, now)` enqueues a job only when due, judged by `created_at` of jobs of that kind in any status: `weather_sync` when local time is past 14:00 and no `weather_sync` job was created since today's 14:00 local; `forecast_refresh` when none was created in the last 6 h. Uses the fixed dedupe keys, so restarts and redeploys never double-enqueue; no-op when `weather_enabled` is false.
- `analytics/pipeline.py`: `@dataclass(frozen=True) class RecomputeStep: name: str; order: int; run: Callable[[Session], None]`; `discover_steps() -> list[RecomputeStep]` (imports every module in `analytics/steps/`, each exposes `STEP`); `run_pipeline(session) -> list[str]` runs steps by `order` then bumps `data_version`. Step orders: `10 metrics` (Plan 06), `20 event_weather` (Plan 05), `30 skill` (Plan 06), `50 achievements` (Plan 10), `60 insights` (Plan 12). Leaderboards, records etc. are computed on demand (cached by `data_version`), not stored; insights are the exception and are stored by step 60 (static until the next pipeline run). **Never edit `pipeline.py` to add a step.**

Forecast-dependent code (Plan 11 predictions, any profile expectation) is never memoized by `data_version` alone: its cache key includes `forecast_cache.fetched_at`.

Wins, podiums, `season_points` and all achievements are keyed by shooter_id. `compute_event_metrics(rounds) -> pd.DataFrame`.
- `analytics/skill.py` (dynamic Gaussian model, online by date):
  ```python
  DEFAULT_GRID = {"obs_var": (10, 12, 14, 16, 20), "drift_var_per_week": (0.05, 0.15, 0.3), "difficulty_var": (2, 4, 9), "prior_mu": (28, 30, 32), "prior_var": (36, 49)}   # max_var = prior_var
  CALIBRATION_GRID = {"obs_var": (12, 14, 16), "drift_var_per_week": (0.05, 0.15, 0.3), "difficulty_var": (2, 4, 9), "prior_mu": (30,), "prior_var": (49,)}   # 27 points ⊂ DEFAULT_GRID; what s30 uses; unit tests may monkeypatch it
  @dataclass(frozen=True) class SkillParams: prior_mu: float = 30.0; prior_var: float = 49.0; obs_var: float = 14.0; drift_var_per_week: float = 0.3; difficulty_var: float = 4.0; max_var: float = 49.0
  @dataclass(frozen=True) class SkillResult: rounds: pd.DataFrame  # round_id, expected, residual, mu_before, var_before, mu_after, var_after (published scale)
                                           events: pd.DataFrame  # event_date, difficulty (published), d_raw, level (L_t)
                                           history: pd.DataFrame # shooter_id, event_date, mu (published scale), var
                                           final_state: dict[int, tuple[float, float, date]]  # shooter → (mu, var, last_date), raw scale
                                           current_level: float  # L at the last event
  def run_skill_model(rounds: pd.DataFrame, params: SkillParams = SkillParams()) -> SkillResult
  def calibrate(rounds: pd.DataFrame, grid: Mapping[str, Sequence[float]] = DEFAULT_GRID) -> SkillParams   # objective below
  def predict(state: Mapping[int, tuple[float, float, date]], shooter_ids: Sequence[int], on: date, params: SkillParams, level: float, difficulty: float | None = None, difficulty_sd: float = 0.0, attend_prob: Mapping[int, float] | None = None, n_sims: int = 10_000, seed: int = 0) -> pd.DataFrame  # shooter_id, attend_prob, expected, sd, p_win, p_podium (semantics in the predict bullet below); `level` = SkillResult.current_level (app_state.skill_level); `difficulty` is on the published scale (positive = harder); expected = mu + level − (difficulty or 0.0); each simulation draws ONE shared day effect ~ N(0, difficulty_sd²) for all shooters; p_win/p_podium are unchanged by the level (owned by Plan 06 T3)
  ```
  Algorithm per held event t (dates ascending; C4 held events):
  1. Each attending shooter i: new → `(mu_i, var_i) = (prior_mu, prior_var)`; else `var_i = min(var_i + drift_var_per_week·days(t − last_i)/7, max_var)`.
  2. `j` ALWAYS indexes shooters, never rounds: `ȳ_i` = mean of i's `k_i` scores that day; `R_i = obs_var/k_i`; `w_i = 1/(var_i + R_i)`; `r_i = ȳ_i − mu_i`.
  3. `P = Σ_j w_j + 1/difficulty_var`; `D = Σ_j w_j r_j`; raw `d_t = D/P`; `P_-i = P − w_i`; `d_-i = (D − w_i r_i)/P_-i`; `V_-i = 1/P_-i`.
  4. Every round of i that day uses the PRE-event state: `expected = mu_i + d_-i + L_t`, `residual = y − expected` (the L_t terms cancel, so the residual is unchanged). All rounds of i share `mu_before/var_before` and `mu_after/var_after`.
  5. `K_i = var_i/(var_i + R_i + V_-i)`; `mu_i += K_i(ȳ_i − mu_i − d_-i)`; `var_i *= (1 − K_i)` (equals the old full-d mean update, stated once without ambiguity).
  - Non-held events: no update — each attendee's drift-inflated mu/var carry forward (`mu_before` = `mu_after`), `expected`/`residual` NULL, difficulty NULL, excluded from `L_t`.
  - Level and sign: `L_t` = mean of raw `d` over events in `(t−364d, t]` (past-only). Published rating = `mu + L_t` — the scale of `rating_history.mu`, `round_metrics.mu_before/mu_after` and `expected`; band = ±1.96·√var. Published `event_metrics.difficulty = −(d_t − L_t)`: positive = harder than a typical recent day, on the backend and in the UI. s30 stores `current_level` in `app_state.skill_level`.
  - `calibrate` maximizes Σ_t log MVN(y_t; m_t, Σ_t) over held score events after the first 8 (burn-in): y_t = all rounds at event t in (name_key, ordinal) order per shooter; m_r = the pre-event, drift-inflated mu of that round's shooter; Σ_t = obs_var·I + Z·diag(var_i)·Zᵀ + difficulty_var·11ᵀ, Z maps rounds to shooters; use `np.linalg.slogdet`/`solve`. Exhaustive search over the `grid` argument (max_var = prior_var); ties go to the lexicographically first point. `DEFAULT_GRID` (270 points) is the documented full search space and the argument default; s30 always passes `CALIBRATION_GRID` (Plan 06 T4), so there is no Settings flag. Fixture (per shooter-day): new defaults ≈ −2.911, old defaults −2.950, best grid point −2.909.
  - No-leak holds for fixed `SkillParams`. Optional, off by default: `newcomer_drift_var_per_week: float | None = None`, gridded over {None, 1.0} (gain ≈0.005 nats per shooter-day); nulling `event_metrics.difficulty` for burn-in events is optional too.
- `predict` semantics (Plan 06 T3):
  - Each shooter's var is drift-inflated from `last_date` to `on` (`min(var + drift_var_per_week·days/7, max_var)`); `expected` is as in the signature comment; `sd = √(var + obs_var + difficulty_sd²)`.
  - Each simulation draws ONE shared day effect, attendance `A_j ~ Bernoulli(attend_prob_j)` (None → 1.0 for all), skill `~ N(mu_j, var_j)` and noise `~ N(0, obs_var)`. Scores are rounded to int and clipped to 0..50, so integer ties occur.
  - All p_* are conditional on i attending. `p_win_i` = mean over sims with A_i = 1 of 1{y_i ≥ max_{j≠i, A_j=1} y_j}, where the max over an empty set is −∞. Ties count as wins, matching min-rank `event_rank == 1` and `first_win`; Σ p_win may exceed 1. A split-credit number, if wanted, is a separate column `p_outright` = P(y_i > max_{j≠i} y_j).
  - `p_podium_i` = P(1 + #{attending j≠i: y_j > y_i} ≤ 3).
  - The Home card may show `p_win × attend_prob` as "chance to win next Sunday".
- Activity: `rolling_12` = event_date in (as_of − 364d, as_of], which is exactly 52 Sundays. A shooter is *active at as_of* iff they have ≥1 round in the rolling_12 window AND ≥5 rounds with event_date ≤ as_of, counted from `rounds` (not rating_history). The `rating` leaderboard ("active only") and the insights' active population use this same definition (`analytics/leaderboards.py:active_shooter_ids(rounds, as_of)`).
- Leaderboard periods: `season` (calendar year of `as_of`, Jan 1..as_of), `rolling_12` ((as_of − 364d, as_of], 52 Sundays), `all_time`. Metrics & min-round thresholds (season / rolling_12 / all_time): `avg_score` S/8/15, `avg_adjusted` S/8/15 (S = season threshold below), `best_score` 1/1/1, `wins` –, `podiums` –, `events` –, `rounds` –, `rating` (active at as_of, per Activity above), `most_improved` (defined below), `season_points`. Season points per event by best-round rank: 1st 10, 2nd 8, 3rd 6, 4th 5, 5th 4, 6th 3, 7th 2, 8th 1, +1 participation; ties get the points of the shared rank.
- `most_improved`:
  - Δ = mu at the last event ≤ as_of minus mu at the last event strictly before the period start.
  - Eligible iff ≥10 rounds before the period start AND ≥5 rounds inside the period.
  - For `all_time`, the start mu is the mu after the shooter's 10th round, and eligible iff ≥15 rounds.
  - Sort by Δ desc, then name_key.
- Season threshold S (for `avg_score` and `avg_adjusted` only) = min(5, max(1, ceil(0.4·E))), where E = has_scores events in [Jan 1, as_of]. The `rolling_12` and `all_time` thresholds are unchanged. `LeaderboardOut` includes `min_rounds_applied` and `n_eligible`, so the UI can show "Needs ≥N rounds" instead of a blank board.
- Season naming:
  - Leaderboard period `season` = calendar year.
  - `Dim.SEASON` and `splits?by=season` = the month-based label only, from the single definition `frames.season_label(event_date)` (Plan 06 T1): winter Dec–Feb, spring Mar–May, summer Jun–Aug, fall Sep–Nov. Sort order is winter, spring, summer, fall. No year is attached.
  - December counts toward the next year's winter only for the `four_seasons` achievement (C12).
- Global round-type filter: `frames.apply_round_type_filter(df, round_types: Sequence[RoundType]) -> pd.DataFrame` (Plan 06 T1). An empty list means no filter. It filters on the event-level `round_type`.
- Status and gauge filters (leaderboards and Explorer only):
  - `status` matches `shooter_profiles.status`, the current status after `set_status` overrides, not per-round `rounds.status`. `gauge` matches the normalized `gauge_class` (NULL = `unspecified`).
  - `event_rank`, `percentile`, `wins`, `podiums` and `season_points` always use full-field `round_metrics.event_rank` and are never recomputed inside a filtered subset. Filters only choose which rounds or shooters are counted.
  - Rating, predictions, achievements and insights ignore all filters.
- Weather bands (single definition: `frames.temp_band(temp_f)`, `wind_band(gust_mph)`, `precip_band(precip_in)`, Plan 06 T1; reused by Plan 06 T6, Plan 07 T7, Plan 11 T2), half-open [lo, hi): temp `<40`, `[40,55)`, `[55,70)`, `[70,85)`, `≥85` °F; wind by gust `<10`, `[10,20)`, `≥20` mph; precip `dry` (<0.02 in), `wet` (≥0.02 — the same threshold as condition `rain` and achievements `rain`/`mudder`). Condition label rule order: `rain` if precip ≥0.02 in over window; `windy` if gust ≥20; `overcast` if cloud ≥75%; `partly_cloudy` if cloud ≥30%; else `clear`.
- Event-window aggregation (Plan 05 T3 `weather/aggregate.py`, which alone defines `WINDOW_FIELDS`, `ACCUMULATION_HOURS` and `ACCUMULATED_FIELDS`; `weather/forecast.py` and `weather/sync.py` import them), per field:
  - `temp_f`, `apparent_f`, `wind_mph`, `cloud_pct`, `humidity_pct`, `pressure_hpa`: arithmetic mean of the 10:00, 11:00 and 12:00 rows; `wind_dir_deg`: speed-weighted circular mean of the same three rows.
  - `precip_in`: SUM of the 11:00 and 12:00 rows (Open-Meteo precipitation is a preceding-hour sum, so these two rows cover exactly 10:00–12:00); `rain_in` is not aggregated (`event_weather` has no such column).
  - `gust_mph`: MAX of the 11:00 and 12:00 rows for both sources (no branching on `source`).
  - `event_weather` is written only when every row these rules need is present; if any is missing, the event is skipped.

### C8. API surface (response models named `<Thing>Out`)
Public: `GET /api/health` → `{status, version}`; `POST /api/auth/login {password}` → `{role}` + cookie `sc_session` (httpOnly, Secure unless `settings.cookie_secure` is false, SameSite=Strict, max-age 30d viewer / 12h admin); `POST /api/auth/logout` (clears the cookie, Max-Age=0); `GET /api/auth/me` → `{role}` | 401. Login rate limit: 10 failures / 15 min / IP → 429 (`login_max_failures` / `login_window_minutes`; checked before any hashing).
- Sessions: `sessions.py` uses `URLSafeTimedSerializer(session_secret, salt='sc-session')` over `{r: role, k: fp}`, fp = first 16 hex chars of HMAC-SHA256(session_secret, current password hash for that role). `load_session` enforces `TTL[role]` (viewer 30d, admin 12h) via the signed timestamp (`loads(..., return_timestamp=True)`), never the cookie Max-Age, and rejects a token whose fp differs from the current hash, so rotating one role's password revokes only that role's sessions.
- Client IP contract: only Caddy reads forwarding headers. Caddy sets `X-Real-IP {client_ip}` (always overwriting any client-sent value) using `trusted_proxies` from env `TRUSTED_PROXIES` (Plan 01 T4). The API takes the client IP from `X-Real-IP`, falling back to `request.client.host`, in one helper `auth/deps.py:client_ip(request) -> str` (IPv6 bucketed by /64), used by `ratelimit.py` and `record_audit`. uvicorn runs with `--no-proxy-headers` and no `--forwarded-allow-ips`. `api` publishes no ports and never joins `traefik_public`.
